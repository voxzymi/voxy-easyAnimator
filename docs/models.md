# Models

Both dissection models are exported to ONNX and live in versioned folders:
`models/general/<version>/model.onnx` + `model.json`, `models/hair/<version>/...`, `models/inpaint/<version>/...`, `models/matting/<version>/...`.
The service loads the version named in `configs/service.yaml`. `model.json` holds the input size, output names, class list (the service
refuses a model whose class list does not match), license note, training-data note, SHA-256, and the parity check against PyTorch.

## General dissection model (`training/general`)

| | |
|---|---|
| Input | `[1, 4, S, S]`: RGB in [-1, 1] (transparent areas white) and a foreground mask. Letterboxed to S x S (`voxy_service/preproc.py`, shared with training). Default S = 512. |
| `seg` | `[1, 22, S, S]` class logits. Class 0 is background; 21 part classes; **hair is one class**. Loss: Dice + cross-entropy. |
| `kpt` | `[1, 15, S/4, S/4]` heat-maps: eyes, mouth, shoulders, elbows, wrists, hips, knees, ankles. Loss: MSE. |
| `amodal` | `[1, 4, S, S]` logits: full extent of head, eye_l, eye_r, mouth. Loss: BCE + Dice. |
| `completion` | `[1, 3, S, S]` RGB in [0, 1]: what is under whatever covers those parts. Loss: L1 (weight 1 on covered pixels, 0.1 elsewhere). |
| Group | Derived from the class (fixed table). No group head. |

`_l` / `_r` are the character's own left and right. Mirroring swaps them (`FLIP_CLASS`, `FLIP_KEYPOINT`).

## Hair subdivision model (`training/hair`)

| | |
|---|---|
| Input | `[1, 4, S, S]`: RGB of the hair crop in [-1, 1] and the hair mask (crop + letterbox in `hair_input`). Default S = 256. |
| `flow` | `[1, 2, S, S]` strand direction (normalised outside the network). Loss: **angular error** on the unit direction (1 - cos). |
| `roots` | `[1, 1, S, S]` logits: where strands start. Loss: BCE with a positive weight. |
| Data | Hair-specific only: synthetic strands (flow traced from roots), reference hair sheets, labeled hair sections. It never sees character labels. |
| Split | Geometry, not ML: `voxy_service/hair/subdivide.py`. |

## Shared

- **Background matting** (Background Removal): default is a deterministic flood-fill key from the picture border (`matting.py`), exact for
  the flat or gradient backgrounds the guide recommends and it keeps background-coloured areas that are enclosed by the character
  (a white eye on a white background). An ONNX matter is supported (`models/matting/<version>`, input `[1,3,S,S]` ImageNet-normalised,
  output alpha) but **none ships**. Documented alternatives (from memory: *verify each license and the training data's provenance
  before bundling*): an anime-trained ISNet segmentation (`skytnt/anime-segmentation`, Apache-2.0 code; weights' data provenance must be
  checked), BiRefNet (MIT code; check weights), U2-Net (Apache-2.0, general purpose). Avoid weights under non-commercial licenses.
- **Inpainting** (Background redraw): two engines the user chooses between. (1) a **colour-aware patch fill** (`inpaint.py`): Lab colour,
  onion-peel order, best masked-SSD patch; good for flat or gently shaded backgrounds. (2) a **large-mask network** loaded from
  `models/inpaint/<version>` (inputs `image [1,3,S,S]`, `mask [1,1,S,S]`, output `[1,3,S,S]`). `training/inpaint` fine-tunes a compact
  dilated-convolution inpainter on the generated occlusion pairs with **L1 + perceptual loss** and an option to freeze the encoder.
  A stronger LaMa-style base (e.g. an Apache-2.0 LaMa ONNX export) can be dropped in with the same contract: verify its license first. Both
  engines fill a ring around the character and cross-fade the edge, so no seam shows.
- **Upscaling**: `upscayl-ncnn` as a subprocess (AGPL-3.0, see `THIRD_PARTY_NOTICES.md`). Flags used, read from the tool's own source and
  re-checked at run time with `-h`: `-i -o -z -s -n -m -t -g -f`. `-z` is the model's native scale, `-s` the output scale.
  Large pictures are tiled by Voxy (overlapping tiles, stitched exactly); `-t` starts at auto and halves after an out-of-memory failure.

## Data and licenses

- Synthetic data is generated by this repository's code (`training/shared/procedural_art.py`): original characters, **CC0**.
- `data/raw/PROVENANCE.csv` must have a row (source, author, license, permission, hash) for every reference image. A sheet with no row,
  an empty license, `owner-permission` without the permission text, a non-commercial license, or a changed hash is **refused**; with
  `--allow-internal` it can be used and the dataset is marked **not shareable**.
- No pretrained weights are bundled. The optional VGG16 weights for the perceptual loss are provided by the developer.

## Speed and limits

Measured on this development machine (4 CPU cores, **no GPU**): the stub pipeline cuts a 640x400 picture in about 0.1 s; an exported
tiny ONNX model (128 px) runs in tens of milliseconds on CPU. Production numbers on the RTX 3060 were **not measured**; see
[memory.md](memory.md) for memory estimates.
